# Supabase setup

The website works without Supabase: it then shows the built-in content from `src/content/defaults.ts`, prices from `src/lib/calculator.ts`, and `/admin` explains that it is not connected yet. With Supabase, Dennis manages that content himself.

## 1. Apply the migrations

Run the files in [migrations](./migrations) in order (Supabase CLI `supabase db push`, or paste them into the SQL editor):

| File | What it does |
| --- | --- |
| `20261008123000_create_reviews.sql` | Review submissions (already live). |
| `20261023120000_cms.sql` | Admin accounts, projects, photos, texts, FAQs, business details, calculator prices, quote requests, the `project-photos` storage bucket and all permissions. Also stops the public key from reading reviewers' e-mail addresses. |
| `20261023120100_cms_seed.sql` | Fills the new tables with the content the site shows today. Generated by `npm run cms:seed-sql`; existing rows are never overwritten. |

Both new migrations can safely be run more than once.

## 2. Environment variables (Vercel)

| Variable | Where | Purpose |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | browser | Project URL. |
| `VITE_SUPABASE_ANON_KEY` | browser | Public (anon) key. Safe to expose: every table is protected by row level security. |
| `SUPABASE_URL` | server | Same URL, for `api/*`. |
| `SUPABASE_SERVICE_ROLE_KEY` | server only | Lets `api/offerte.ts` store quote requests and `api/review*.ts` handle reviews. Never prefix with `VITE_`. |
| `RESEND_API_KEY`, `RESEND_FROM_EMAIL` | server | E-mail delivery. |
| `QUOTE_RECIPIENT_EMAIL`, `REVIEW_RECIPIENT_EMAIL` | server | Inboxes for quote requests and review moderation. |
| `PUBLIC_SITE_URL` | server | Used in e-mail links. |

## 3. Give Dennis an admin account

1. In Supabase: **Authentication → Users → Add user**, with Dennis's e-mail address and a strong temporary password (or send an invite).
2. In the SQL editor:

   ```sql
   insert into public.admin_users (user_id, display_name)
   select id, 'Dennis' from auth.users where email = 'info@denrabadkamers.nl';
   ```
3. Turn off public sign-ups (**Authentication → Providers → Email → Allow new users to sign up: off**). Accounts without a row in `admin_users` cannot change anything anyway, but there is no reason to let strangers create them.
4. Set **Authentication → URL Configuration → Site URL** to the live domain and add `https://denrabadkamers.nl/admin/nieuw-wachtwoord` to the redirect URLs, so "Wachtwoord vergeten?" works.

## How permissions work

- Visitors (anon key) can read published projects and their photos, visible FAQs, website texts, business details, calculator prices and approved reviews (without e-mail addresses). Nothing else.
- Every change requires a logged-in user listed in `public.admin_users`; the check (`public.is_admin()`) runs in the database, in the row level security policies and in the save functions (`save_project`, `reorder_projects`, `save_faqs`, `save_calculator`). Hiding menu items in the admin is only a convenience.
- Quote requests are inserted only by `api/offerte.ts` with the service-role key. Admins can change just their status and notes.
- `api/offerte.ts` recalculates every price from the price list in the database (or the built-in list without Supabase) and refuses unknown or conflicting options; the amount from the browser is stored only for comparison.

## Reviews

Each submitted review is stored as `pending`. The moderation e-mail links to a confirmation page: opening a link never changes anything, only the button on that page does. Dennis can also approve or remove reviews under **Reviews** in the admin. The reviews in `src/data/reviews.ts` are always shown; a submitted review with the same name and text as one of those is shown once.

## Testing

- `npm run test:db` applies all migrations to an in-process Postgres and checks who may read and change what.
- `tools/local-supabase` runs the whole site and admin against a local database; see its README.
